# V0.7.3 回归测试清单

## 一、升级、登录与用户

- [ ] 使用旧版`deliverables.db`启动，原交付物、版本和变更数据仍存在。
- [ ] 登录成功后主页面从顶部显示，不需要向下滚动。
- [ ] 管理员可新增、编辑、重置密码和删除用户。
- [ ] 当前登录账号不能删除。
- [ ] 最后一个启用管理员不能删除。

## 二、仪表盘与完整度说明

- [ ] 仪表盘全部统计卡片和分析模块标题后显示说明图标。
- [ ] 完整度分析全部指标卡片和分析模块标题后显示说明图标。
- [ ] 鼠标悬停和键盘Tab聚焦均能显示完整统计规则。
- [ ] 说明中的状态、时间范围、计算公式和排除规则与页面数字一致。

## 三、交付物编码与自动版本号

- [ ] 台账“交付物编码”表头显示规则说明。
- [ ] 新增交付物编码由系统生成且不可手工修改。
- [ ] 新增交付物首个版本固定为`V1.0.0`。
- [ ] 修订、功能、重大版本分别按三级版本规则自动生成。
- [ ] 已存在更高版本时，以全部合法版本中的最高版本继续计算。

## 四、基线前版本互斥

- [ ] 新建交付物后首个版本为草稿，详情页“新增迭代版本”按钮禁用。
- [ ] 草稿版本未提交审批时，调用新版新增版本接口返回明确错误。
- [ ] 草稿版本未提交审批时，调用旧版新增版本接口同样不能绕过限制。
- [ ] 草稿提交审批后处于“审批中”，仍不允许创建第二个版本。
- [ ] 审批中版本退回草稿后，仍不允许创建第二个版本。
- [ ] 管理员在存在草稿或审批中版本时也不能使用补录入口绕过互斥规则。

## 五、审批与发布分离

- [ ] 草稿版本点击“提交审批”后进入“审批中”。
- [ ] 审批中版本显示“退回修改”和“审批通过”，不显示“正式发布”。
- [ ] 点击“审批通过”并填写审批意见后进入“待发布”。
- [ ] 审批通过不会更新交付物当前版本，也不会填写正式发布日期。
- [ ] 版本进入“待发布”后，基线形成前允许创建后续迭代版本。
- [ ] 待发布版本可以废止，审批和生命周期记录仍保留。

## 六、最高有效版本发布约束

- [ ] `V1.0.0`待发布且没有更高有效版本时，可以正式发布。
- [ ] `V1.0.0`待发布后创建`V1.0.1`草稿，`V1.0.0`发布按钮禁用。
- [ ] 直接调用接口发布`V1.0.0`时，后端返回“存在更高版本”的明确错误。
- [ ] `V1.0.1`审批通过后可以正式发布并成为当前版本。
- [ ] 高版本发布后，低版本即使后续审批通过也不能覆盖当前高版本。
- [ ] `V1.0.1`已经作废后，如果`V1.0.0`仍处于待发布状态，`V1.0.0`恢复为可发布状态。
- [ ] 已作废版本不参与最高有效版本排序，但仍保留历史记录。
- [ ] 版本比较按三级数字规则执行，不按字符串字典序比较。
- [ ] 发布后原当前版本变为“已替代”。

## 七、版本详情

- [ ] “版本记录”每一行均显示“详情”按钮。
- [ ] 点击“详情”打开版本详情弹窗，不跳转页面。
- [ ] 详情展示内部版本、原始版本、原始文件名、统一文件名、服务器路径、校验值、状态、审批人、发布时间等公共字段。
- [ ] 硬件软件包展示硬件类别、型号、供应商、软件包类型、刷写方式等专属字段。
- [ ] PRD展示产品模块、功能名称、需求来源、目标车型、目标节点等专属字段。
- [ ] FR展示所属系统、功能模块、上游PRD、目标软件基线、接口影响等专属字段。
- [ ] 测试用例展示测试级别、模块、上游FR、用例数量、测试环境等专属字段。
- [ ] 无值字段统一显示“—”，日期和文件大小按可读格式展示。

## 八、基线后受控变更

- [ ] 首个版本正式发布后，编辑者不再显示“新增迭代版本”。
- [ ] 已形成基线后详情页显示“发起变更”。
- [ ] 已形成基线后普通新增版本的新旧接口均不能绕过变更流程。
- [ ] 发起变更自动锁定当前有效已发布版本。
- [ ] 变更批准并进入实施后才允许创建变更版本。
- [ ] 变更版本同样遵循草稿/审批中互斥和最高有效版本发布规则。
- [ ] 变更版本未正式发布时不能关闭变更。

## 九、变更时间线与其他能力

- [ ] 台账“变更记录”从右侧打开时间线抽屉并按由近到远展示。
- [ ] 台账和变更管理可选择字段导出CSV，中文Excel打开不乱码。
- [ ] 交付物关联支持新增、查看、跳转和删除。
- [ ] 用户删除、权限限制和审计日志工作正常。
