# Jira关闭复盘验证清单

## 统计边界

1. 为两个项目的同一严重等级设置不同关闭总周期（例如10天和21天），查询相同耗时的问题，确认按所属项目分别判定。
2. 修改时效标准后重新分析，确认卡片、对比图、明细一起应用新值；已保存的复盘快照保持原标准版本。
3. 验证耗时等于时限、超过时限1秒、缺少时限、缺少关闭日期和不完整历史。超期天数向上取整，按期判定不使用显示值的四舍五入结果。
4. 一条阶段超期但关闭总周期达标的问题，应算按期且允许复盘；完全未超期的问题不可复盘。
5. 多查询方案重复命中只计一次；同项目方案使用不同严重等级字段应在查询前纠正，保证统计定义一致。
6. 周/月/年、同比/环比、跨年ISO周、闰年、短月和当前半周期均检查分子、分母和样本量。基期零、空样本显示说明。
7. 关闭后重新打开、再次关闭和同一阶段多次进入，确认历史关闭事件与阶段累计时间正确。当前未关闭不应抹去早期周期末已关闭的记录。

## 复盘与权限

1. 首列为操作；筛选项目、严重等级、关闭时效、阶段、关闭日期和复盘状态；从明细进入复盘后保留列表筛选。
2. 空原因、空责任人、无分类不能保存；后台同样拒绝非法输入。供应商责任人可自由填写。
3. 保存后刷新、重新登录仍能查看；其他有查看权限的用户可查看共享记录；重复保存得到具体提示。
4. 两人同时修改同一复盘，旧修订号更新与删除均被拒绝。编辑不改写问题及标准快照。
5. 无查看权限无法访问列表；只读账号不能新增、编辑、删除；各写接口校验独立权限。字典分类选择不要求字典管理权限。
6. 切换Jira服务器后无法读取或修改其他服务器的复盘。直接请求接口无法绕过来源校验。
7. 被引用的分类无法删除；错误分类ID及其他字典的ID不能保存。删除复盘后引用计数减少。
8. 查看菜单三项分析与当前筛选后的列表一致；多阶段超期可贡献多条阶段统计，问题数量仍去重。
9. 校验CSV筛选结果、长文本转义、表格首列、移动端滚动、加载失败重试，以及PDF包含新增卡片和两张对比图。

## 按期穿透与阶段累计调整

- “按期关闭率（总周期）”仅穿透总周期达标的已关闭问题；清空筛选条件仍限定在该范围。总周期超期和无法判定的问题不进入该列表，“已关闭问题”入口继续展示全部已关闭问题。
- 已关闭明细、超期处理分析及对应CSV移除“是否关闭超期”列。
- “超期天数”统一累计各阶段已向上取整的超期天数，例如分析超期4天、修复超期3天，累计显示7天。阶段数据或标准不完整时显示“无法判定”，不使用总关闭周期超期天数代替。
- 验证通过：12项Node回归；Chromium模拟接口验证按期穿透范围、清空筛选、实际CSV下载、两处列表阶段累计显示，并通过现有复盘和多窗口布局回归。未执行.NET构建或真实Jira联调。


## 关闭时间与按期率口径修正

- 总览：确认按期数 / 所有已关闭问题数；无法判定留在分母。23条已关闭中20条按期、2条超期、1条未知，应显示87.0%。全未知且有已关闭问题显示0%，没有已关闭问题显示“—”。
- 关闭节点：以所配置关闭状态的最后一次状态操作时间为准；关闭状态A转关闭状态B取B的操作时间；重开再关闭取最新关闭操作。只有解决日期、没有关闭状态操作时间时，不推测关闭日期。
- 时效比较：使用原始时间差与当前项目、当前严重等级的关闭总周期比较；等于时限按期，超1秒不按期。阶段超期不改变总周期按期判定。
- 同比/环比：选周期末最新关闭操作，分母包含周期中能归档的全部已关闭样本；连续关闭状态之后重开，不能回退到更早关闭事件补入样本。无关闭操作时间的记录不能归档，在图表说明中提示。
- 修改Jira时效标准后重新分析；新增复盘使用服务端同一解析逻辑。已有复盘的审计快照保持保存时数据，不自动重写。
- 本次Node统计与浏览器模拟接口回归覆盖分母、未知样本、连续关闭/重开、跨周期、精度和卡片穿透；服务端关闭节点调整已做代码链路检查，未执行.NET构建或真实Jira接口验证。手动构建后请重点验证关闭A→关闭B、重开后再关闭、缺少操作历史及临界时限。
